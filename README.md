# JUT ReAttempter

A JEE Main–style CBT (computer-based test) practice app. Pick any combination
of JUT test numbers you've attempted before, and it assembles a **brand-new,
randomized 75-question paper** (20 MCQs + 5 numerical-value questions per
subject — Physics, Chemistry, Mathematics) pooled only from the tests you
chose. Attempt it in an NTA-faithful interface with a strict 3-hour timer,
then get a server-verified scorecard.

## Quick start

```bash
pip install -r requirements.txt
python app.py
```

Open **http://127.0.0.1:5000** in your browser. That's it — no database, no
build step. The app needs internet access in the *browser* (not the server)
to load Google Fonts and MathJax from their CDNs; everything else is served
locally.

## Using your real question bank

The app ships with `data/questions.json`, a **synthetic sample** (6 JUT
tests, 450 questions) generated by `generate_sample_data.py` purely so the
app has something to run against out of the box.

To use your real data, replace `data/questions.json` with your own export —
same schema you already have:

```json
{
  "exam": "JEE",
  "exam_type": "JUT",
  "exam_number": "01",
  "exam_id": 9460,
  "question_number": 1,
  "subject": "Physics",
  "question_type": "MCQ",
  "question_html": "...",
  "question_text": "...",
  "options": [{ "html": "...", "text": "1 ) ..." }],
  "correct_answer": "1",
  "your_answer": "",
  "solution_html": "...",
  "solution_text": "..."
}
```

Notes on how the backend reads this:

- **Test grouping** is by `exam_type` + `exam_number` (so all questions with
  `exam_number: "11"` become "JUT 11" in the picker).
- **MCQ vs numerical** is decided by `question_type` (`"MCQ"` → MCQ; anything
  like `"Numerical"` / `"Integer"` / `"SA"` → numerical), falling back to
  "no `options` array → numerical" if the field is missing or unrecognized.
- Each question needs a unique `(exam_id, question_number)` pair — that's
  used as its internal ID.
- `question_html` / `solution_html` can contain raw **MathML** `<math>…</math>`
  tags (exactly like your sample) — the frontend renders these directly via
  MathJax's `mml-chtml` component, no conversion needed.
- Restart the Flask process after swapping the file (it's loaded once at
  startup).

You don't need every subject/test to have exactly 20+5 questions — if a
selected pool comes up short for a subject, the app fills in what's
available and reports the shortfall in the picker's response (surfaced as
a warning banner).

## How scoring works

Marking follows the current JEE Main scheme, applied server-side against the
answer key stored in memory for that session — the browser never sees
correct answers until after submission:

| Type | Correct | Incorrect | Unattempted |
|---|---|---|---|
| MCQ | +4 | −1 | 0 |
| Numerical | +4 | 0 | 0 |

Both are configurable at the top of `app.py` (`MARKS_MCQ_CORRECT`, etc.).

## A couple of deliberate calls I made

- **Manual submit is always available**, with a confirmation dialog showing
  your answered/unanswered/marked tally. The literal NTA behaviour ("Submit
  disabled until the timer ends") would make a *practice* tool unusable, so
  the strict part I kept is the **timer itself** — it auto-submits the
  instant it hits zero, no extension, no warning dismissal.
- **Sessions and results live in server memory** (`SESSIONS` / `RESULTS`
  dicts in `app.py`), which is fine for local/single-instance use. For a
  multi-user deployment you'd want to move these to Redis/a database and add
  session expiry cleanup on a schedule rather than per-request.
- Client progress (current answers, timer end-time) is mirrored into
  `sessionStorage` so a refresh mid-test doesn't lose your work — closing the
  tab does, same as a real exam center's session.

## Project layout

```
app.py                    Flask app: routes + generation + scoring
generate_sample_data.py   Builds the demo data/questions.json
data/questions.json       Question bank (replace with your real export)
templates/                index.html · select.html · test.html · result.html
static/css/               style.css (shared/landing/picker) · exam.css · result.css
static/js/                theme.js · icons.js · select.js · exam.js · result.js
```

## Browser support notes

Built and tested against current Chrome/Edge/Firefox/Safari. Uses
`color-mix()` in CSS for a couple of tint effects — supported in all
evergreen browsers as of 2024+; if you need to support something older,
those specific declarations (search `color-mix`) have straightforward
static-hex fallbacks you can swap in.
